    Agent Teams¶

    Agent Teams는 여러 Claude Code 인스턴스가 하나의 팀으로 협업하는 기능입니다. 하나의 세션이 리드(Lead) 역할로 작업을 조율하고 태스크를 할당하며 결과를 종합합니다. 팀원(Teammate)은 각자 독립된 컨텍스트 윈도우에서 작업하고, 서로 직접 메시지를 주고받을 수 있습니다.

    warning¶

    Agent Teams는 실험적 기능으로 기본 비활성화되어 있습니다. 팀원마다 독립된 컨텍스트 윈도우를 사용하므로 단일 세션보다 토큰을 훨씬 많이 소비합니다.

    리드와 팀원이 공유 태스크 리스트로 작업을 관리합니다. 리드가 태스크를 직접 할당할 수도 있고, 팀원이 남은 태스크를 스스로 가져갈(Self-claim) 수도 있습니다. 대부분의 작업에는 3~5명 규모의 팀이 권장됩니다. 서로 다른 가설로 나누어 진행하는 디버깅, 프론트엔드와 백엔드처럼 레이어 간 조율이 필요한 기능 구현, 리서치와 리뷰 작업에 적합합니다.

    CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 환경 변수를 설정해 활성화합니다.

    .claude/settings.jsonJSON
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

    별도 명령 없이 자연어로 팀 구성을 요청하면 됩니다.

    PROMPT
팀원 3명을 만들어서 이 버그의 원인을 서로 다른 가설로 조사해 줘

    Dynamic Workflows와의 비교해서 두 기능 모두 여러 에이전트를 활용하지만, 계획을 누가 들고 있는지가 다릅니다. Dynamic Workflow는 계획을 코드로 옮긴 것입니다. 스크립트가 루프, 분기, 중간 결과를 직접 들고 있어 Claude의 컨텍스트에는 최종 결과만 남습니다. 반면 Agent Teams는 리드 에이전트가 오케스트레이터로서 턴마다 다음에 무엇을 할지 결정하고, 진행 상황을 공유 태스크 리스트로 관리합니다.

    **토큰 사용량은 subagent보다 많을 수 밖에없음. !

    |-|-|-구분 Dynamic Workflows Agent Teams 계획 보유 스크립트(코드) 리드 에이전트(턴 단위 결정) 규모 한 번에 수십~수백 개 에이전트 소수(3~5명)의 장기 실행 팀원 에이전트 간 통신 없음(스크립트에만 결과 보고) 팀원 간 직접 메시징 중간 결과 위치 스크립트 변수 공유 태스크 리스트 실행 중 사용자 개입 불가 가능(리드와 대화) 적합한 작업 대규모 일괄 작업(버그 스윕, 마이그레이션, 교차 검증 리서치) 협업이 필요한 작업(가설 분담 디버깅, 레이어 간 조율)
